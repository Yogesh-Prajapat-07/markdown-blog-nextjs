# TypeScript Tutorial: Beginner to Advanced

TypeScript is a programming language built on JavaScript that adds a static type system. It helps developers catch many mistakes during development, document data shapes, and improve editor support. TypeScript code is typically compiled or transformed into JavaScript before execution.

This guide moves from basic types to more advanced patterns, with examples for everyday JavaScript, React, and backend development.

## 1. What Is TypeScript?

TypeScript extends JavaScript with types and other developer-oriented features. Most valid JavaScript is also valid TypeScript, although a TypeScript project may report type errors that plain JavaScript does not.

### Why use TypeScript?

- Catch many type-related errors before runtime.
- Improve autocomplete and refactoring in editors.
- Make function inputs and outputs easier to understand.
- Share clear data contracts across a codebase.
- Improve maintainability as projects grow.

TypeScript types are primarily checked during development and compilation. They do not automatically validate incoming JSON or other untrusted runtime data.

## 2. Setup and Compilation

Make sure Node.js is installed, then create a project:

```bash
mkdir typescript-learning
cd typescript-learning
npm init -y
npm install --save-dev typescript
npx tsc --init
```

Create `src/index.ts`:

```typescript
const message: string = "Hello, TypeScript!";
console.log(message);
```

Compile the file:

```bash
npx tsc src/index.ts --outDir dist
node dist/index.js
```

The exact output path depends on your TypeScript configuration and command. For a larger project, configure `rootDir` and `outDir` in `tsconfig.json` and use scripts.

Example scripts:

```json
{
  "scripts": {
    "build": "tsc",
    "typecheck": "tsc --noEmit"
  }
}
```

Keep the rest of the fields generated by npm. TypeScript does not need to be installed globally; a project-local compiler helps keep the tool version consistent.

## 3. Basic Types

### String, number, and boolean

```typescript
let username: string = "Yogi";
let age: number = 20;
let isStudent: boolean = true;
```

JavaScript numbers use the `number` type. There is no separate TypeScript type for integers.

### Any

```typescript
let value: any = "hello";
value = 42;
```

`any` disables many type checks for that value. Avoid using it as a shortcut because it removes much of TypeScript's benefit.

### Unknown

```typescript
let input: unknown = "hello";

if (typeof input === "string") {
  console.log(input.toUpperCase());
}
```

`unknown` is safer than `any`: you must narrow the value before using it as a specific type.

### Null and undefined

With strict null checking enabled, handle possibly absent values explicitly:

```typescript
let displayName: string | null = null;

if (displayName !== null) {
  console.log(displayName.toUpperCase());
}
```

## 4. Type Inference

TypeScript often infers a type from the assigned value:

```typescript
let city = "Ahmedabad";
city = "Jaipur";

// city = 123; // Type error
```

You do not need to annotate every variable. Add explicit types where they improve clarity, especially at public function boundaries and data contracts.

## 5. Arrays and Tuples

### Arrays

```typescript
const scores: number[] = [80, 92, 75];
const names: Array<string> = ["Asha", "Yogi"];
```

Both `number[]` and `Array<number>` represent arrays of numbers.

### Tuples

A tuple describes an array with known positions and types:

```typescript
const userRecord: [number, string] = [1, "Yogi"];
```

Use tuples when positions have specific meaning. For ordinary collections, arrays are usually clearer.

## 6. Objects and Type Aliases

Define a reusable object type:

```typescript
type User = {
  id: string;
  name: string;
  email?: string;
  readonly createdAt: Date;
};

const user: User = {
  id: "u1",
  name: "Yogi",
  createdAt: new Date()
};
```

- `email?` is optional.
- `readonly` prevents reassignment through this type, but does not deeply freeze the object at runtime.

Type aliases can also represent unions, function types, and other type expressions.

## 7. Interfaces

Interfaces describe object shapes and are commonly used for public contracts.

```typescript
interface Product {
  id: string;
  name: string;
  price: number;
}

function printProduct(product: Product): void {
  console.log(`${product.name}: ${product.price}`);
}
```

### Interface versus type

Both can describe object shapes. Interfaces support declaration merging and extension; type aliases can represent unions, intersections, primitives, tuples, and other types. Choose based on the shape and project conventions rather than treating one as universally better.

## 8. Functions

Annotate parameters and return values when useful:

```typescript
function add(a: number, b: number): number {
  return a + b;
}

const greet = (name: string): string => `Hello, ${name}`;
```

### Optional and default parameters

```typescript
function welcome(name: string, greeting = "Hello"): string {
  return `${greeting}, ${name}`;
}

welcome("Yogi");
welcome("Yogi", "Welcome");
```

A parameter with a default value can be omitted when calling the function.

### Void and never

`void` commonly describes a function that does not return a useful value:

```typescript
function logMessage(message: string): void {
  console.log(message);
}
```

`never` describes a value that does not occur, such as a function that always throws:

```typescript
function fail(message: string): never {
  throw new Error(message);
}
```

## 9. Union and Literal Types

A union permits one of several types:

```typescript
function printId(id: string | number): void {
  console.log(id);
}
```

Literal types restrict a value to specific options:

```typescript
type Status = "pending" | "in-progress" | "completed";

function setStatus(status: Status): void {
  console.log(status);
}

setStatus("completed");
```

This is often safer than accepting arbitrary strings for known states.

## 10. Type Narrowing

Type narrowing uses checks to make a broad type more specific.

```typescript
function formatValue(value: string | number): string {
  if (typeof value === "number") {
    return value.toFixed(2);
  }

  return value.toUpperCase();
}
```

### Discriminated unions

```typescript
type ApiResult =
  | { success: true; data: string[] }
  | { success: false; error: string };

function showResult(result: ApiResult): void {
  if (result.success) {
    console.log(result.data);
  } else {
    console.error(result.error);
  }
}
```

The `success` property lets TypeScript determine which object shape is available in each branch.

### Type guards

```typescript
function isString(value: unknown): value is string {
  return typeof value === "string";
}
```

A custom type guard should accurately test the claim it makes. Incorrect type guards can hide bugs.

## 11. Generics

Generics let functions and types work with multiple types while preserving information about each type.

```typescript
function identity<T>(value: T): T {
  return value;
}

const text = identity("hello");
const number = identity(123);
```

### Generic constraints

```typescript
function getLength<T extends { length: number }>(value: T): number {
  return value.length;
}

getLength("TypeScript");
getLength([1, 2, 3]);
```

The constraint means that `T` must have a numeric `length` property.

### Generic API response

```typescript
type ApiResponse<T> = {
  data: T;
  message: string;
};

const response: ApiResponse<string[]> = {
  data: ["React", "Node.js"],
  message: "Loaded"
};
```

Generics are useful for reusable utilities, API response shapes, collections, and data-access layers.

## 12. Enums and Alternatives

An enum creates a named set of values:

```typescript
enum Role {
  Admin = "ADMIN",
  Member = "MEMBER"
}

const role: Role = Role.Admin;
```

String literal unions are another common choice:

```typescript
type UserRole = "ADMIN" | "MEMBER";
```

Literal unions are often simple and lightweight. Enums may be appropriate when a named runtime object is useful. Follow the conventions of your codebase.

## 13. Utility Types

TypeScript provides built-in utility types for transforming existing types.

```typescript
type User = {
  id: string;
  name: string;
  email: string;
  active: boolean;
};

type NewUser = Omit<User, "id">;
type UserPreview = Pick<User, "id" | "name">;
type UserUpdate = Partial<User>;
type ReadonlyUser = Readonly<User>;
```

Other useful utility types include:

- `Record<K, V>` — maps keys to values of a given type.
- `Required<T>` — makes properties required.
- `NonNullable<T>` — removes `null` and `undefined`.
- `ReturnType<T>` — extracts a function's return type.
- `Parameters<T>` — extracts a function's parameter tuple.

These types affect compile-time checking; they do not automatically transform or validate runtime data.

## 14. Classes and Access Modifiers

TypeScript supports classes and access modifiers.

```typescript
class Account {
  constructor(
    public readonly id: string,
    private balance: number
  ) {}

  deposit(amount: number): void {
    if (amount <= 0) {
      throw new Error("Amount must be positive");
    }

    this.balance += amount;
  }

  getBalance(): number {
    return this.balance;
  }
}

const account = new Account("a1", 100);
account.deposit(50);
console.log(account.getBalance());
```

- `public` is accessible from outside the class.
- `private` restricts access through TypeScript's type system.
- `readonly` prevents reassignment through the declared type.
- `protected` allows access within the class and subclasses.

TypeScript's `private` modifier is a compile-time restriction. JavaScript's `#field` syntax provides runtime private fields.

## 15. Modules and Imports

Export types and values from one file:

```typescript
// types.ts
export interface Task {
  id: string;
  title: string;
}
```

Import them elsewhere:

```typescript
import type { Task } from "./types.js";

const task: Task = {
  id: "t1",
  title: "Learn TypeScript"
};
```

The appropriate import extension and module resolution depend on your build setup. Follow the conventions established by your `tsconfig.json` and runtime.

Use `import type` when importing types only; it makes the intent explicit and helps avoid unnecessary runtime imports.

## 16. Working with External Data

A TypeScript type does not validate JSON received from a browser, database, or external API. Treat external data as `unknown` until it has been checked.

```typescript
function isUser(value: unknown): value is { id: string; name: string } {
  if (typeof value !== "object" || value === null) {
    return false;
  }

  const candidate = value as Record<string, unknown>;

  return (
    typeof candidate.id === "string" &&
    typeof candidate.name === "string"
  );
}

async function loadUser(): Promise<void> {
  const response = await fetch("/api/user");

  if (!response.ok) {
    throw new Error(`Request failed: ${response.status}`);
  }

  const data: unknown = await response.json();

  if (!isUser(data)) {
    throw new Error("Invalid user response");
  }

  console.log(data.name);
}
```

For complex schemas, a runtime validation library can reduce manual checks. Validate authorization and business rules separately; a valid data shape does not mean a user is allowed to perform an action.

## 17. TypeScript with React

TypeScript works well with React and helps define props, state, and event types.

### Typed props

```tsx
type GreetingProps = {
  name: string;
  message?: string;
};

export function Greeting({ name, message = "Welcome" }: GreetingProps) {
  return <h1>{message}, {name}!</h1>;
}
```

### State

```tsx
import { useState } from "react";

export function Counter() {
  const [count, setCount] = useState<number>(0);

  return (
    <button onClick={() => setCount((current) => current + 1)}>
      Count: {count}
    </button>
  );
}
```

TypeScript can infer `number` here, so the explicit generic is optional.

### Event types

```tsx
import type { ChangeEvent } from "react";

function SearchBox() {
  function handleChange(event: ChangeEvent<HTMLInputElement>) {
    console.log(event.currentTarget.value);
  }

  return <input onChange={handleChange} placeholder="Search..." />;
}
```

Prefer types inferred from React component props where possible, and use the appropriate event type when writing reusable handlers.

## 18. TypeScript with Node.js and Express

Install the needed packages and type definitions according to your selected versions:

```bash
npm install express
npm install --save-dev typescript @types/node @types/express
```

A basic Express handler:

```typescript
import express, { type Request, type Response } from "express";

const app = express();
app.use(express.json());

type Task = {
  id: string;
  title: string;
};

const tasks: Task[] = [];

app.get("/api/tasks", (_req: Request, res: Response<Task[]>) => {
  res.json(tasks);
});

app.listen(5000, () => {
  console.log("Server listening on port 5000");
});
```

This example is intentionally small. For a real API, add input validation, persistent storage, authentication, authorization, and error handling. Types alone do not validate request bodies at runtime.

## 19. tsconfig.json and Strict Mode

`tsconfig.json` controls how TypeScript checks and emits code. A configuration suitable for one project may not be suitable for another.

Useful settings include:

- `strict` — enables a group of stricter type-checking options.
- `noEmit` — type-check without emitting JavaScript.
- `target` — controls the JavaScript language level emitted.
- `module` — controls module output behavior.
- `moduleResolution` — determines how imports are resolved.
- `rootDir` and `outDir` — organize source and output directories.
- `sourceMap` — can help debugging generated JavaScript.

Enable strict checking for new projects when practical and fix errors rather than silencing them indiscriminately. Frameworks and build tools may provide their own recommended configuration.

## 20. Common Mistakes and Best Practices

- Avoid `any` when `unknown` or a specific type is possible.
- Do not use `as` to silence errors without verifying the value.
- Enable strict type checking.
- Use inference for obvious local values.
- Define clear types for API contracts and reusable functions.
- Remember that types disappear at runtime.
- Validate request bodies, query parameters, environment variables, and external JSON.
- Avoid duplicating types that can be safely shared across modules.
- Use discriminated unions to model mutually exclusive states.
- Keep type assertions and custom type guards accurate.
- Do not assume `readonly` deeply freezes an object.
- Do not assume compile-time types replace security checks or database constraints.

## 22. Interview Questions and Answers

### 1. What is TypeScript?

TypeScript is a language that extends JavaScript with static type checking and compiles or transforms to JavaScript.

### 2. Why use TypeScript?

It can catch many type errors before runtime and improves editor support, refactoring, and code documentation.

### 3. Does TypeScript run directly in the browser?

Browsers execute JavaScript. TypeScript is normally compiled or transformed to JavaScript first.

### 4. What is type inference?

Type inference is when TypeScript determines a type from how a value is initialized or used.

### 5. What is the difference between `any` and `unknown`?

`any` disables many type checks. `unknown` requires a value to be narrowed or checked before it can be used as a specific type.

### 6. What is a type alias?

A type alias gives a name to a type expression using `type`.

### 7. What is an interface?

An interface describes the shape of an object or a contract that a value must satisfy.

### 8. What is the difference between `type` and `interface`?

Both can describe object shapes. Interfaces can be extended and declaration-merged; type aliases can represent unions, intersections, and other type expressions.

### 9. What is a union type?

A union type allows a value to be one of several types, such as `string | number`.

### 10. What is a literal type?

A literal type restricts a value to a specific literal, such as `"pending"` or `"completed"`.

### 11. What is type narrowing?

Type narrowing uses checks such as `typeof`, property checks, or discriminant fields to make a broad type more specific.

### 12. What are generics?

Generics let functions, classes, and types work with multiple types while preserving type information.

### 13. What is a generic constraint?

A constraint restricts a generic type to values that satisfy a specified type, often using `extends`.

### 14. What is the difference between `void` and `never`?

`void` commonly means a function does not return a useful value. `never` represents a value that does not occur, such as a function that always throws.

### 15. What is an optional property?

A property marked with `?` may be absent from an object.

### 16. What does `readonly` mean?

It prevents reassignment through that type. It does not deeply freeze an object at runtime.

### 17. What is a tuple?

A tuple is an array type with a defined sequence of element types and positions.

### 18. What are utility types?

Built-in type transformations such as `Partial`, `Pick`, `Omit`, `Record`, and `Readonly`.

### 19. What is `Partial<T>`?

It creates a type in which all properties of `T` are optional.

### 20. What is `Pick<T, K>`?

It creates a type containing selected properties from `T`.

### 21. What is `Omit<T, K>`?

It creates a type by removing selected properties from `T`.

### 22. What is a discriminated union?

It is a union of object types that share a literal-valued property used to distinguish the variants.

### 23. What is a type assertion?

A type assertion tells the compiler to treat a value as a specified type. It does not perform runtime validation.

### 24. What is `tsconfig.json`?

It configures TypeScript compiler options and the project's compilation or checking behavior.

### 25. What does strict mode do?

It enables a group of stricter checks that help catch additional mistakes.

### 26. What is the difference between compile-time and runtime validation?

Compile-time checking analyzes types during development. Runtime validation checks actual values while the program runs.

### 27. Can TypeScript guarantee that API data is valid?

No. External data must be validated at runtime before the application relies on its shape.

### 28. How do you type React props?

Define a type or interface for the props and use it for the component's parameters.

### 29. How do you type a React input change event?

Use an appropriate React event type, such as `ChangeEvent<HTMLInputElement>`, or allow inference from an inline handler.

### 30. Can TypeScript be used with Express?

Yes. Install TypeScript and the relevant type definitions, configure the project, and add runtime validation for external input.

### 31. What is `import type`?

It marks an import as type-only, making it explicit that the imported symbol is used for type checking rather than as a runtime value.

### 32. What is `as const`?

It asks TypeScript to infer literal types and readonly properties or tuples for an expression where applicable.

### 33. What is an enum?

An enum defines a named set of related values. String literal unions are a common alternative.

### 34. Why avoid excessive type assertions?

Assertions can hide mismatches and do not validate runtime values. Prefer inference, narrowing, and validation.

### 35. How should a beginner learn TypeScript?

Start with basic types, objects, functions, unions, and narrowing. Then learn interfaces, generics, utility types, and apply them in React and backend projects.

## Conclusion

TypeScript adds a useful type system to JavaScript and can make growing applications easier to maintain. Start with basic types, functions, objects, and unions. Then practice narrowing, generics, utility types, and strict configuration.

The most important lesson is that TypeScript improves development-time checks but does not replace runtime validation. Use it with React, Next.js, Node.js, and Express to build clearer, more reliable applications.
