# Node.js Tutorial

Node.js lets you run JavaScript outside the browser. It is commonly used to build APIs, backend services, command-line tools, real-time applications, and development tooling.

This guide starts with the fundamentals and moves toward practical backend development. Examples use modern JavaScript ES modules. Test the examples in a local project and adapt configuration before using them in production.

## 1. What Is Node.js?

Node.js is an open-source JavaScript runtime built on the V8 JavaScript engine. It provides APIs for tasks such as networking, file access, cryptography, and interacting with the operating system.

### Common use cases

- REST APIs and backend services
- Real-time applications, such as chat
- Command-line tools
- Build tools and developer utilities
- Streaming and data-processing services
- Backend services for React and other frontend applications

Node.js is especially useful for I/O-heavy applications. CPU-intensive tasks may need worker threads, separate worker processes, or a dedicated service so they do not block the main event loop.

## 2. Install Node.js

Download a supported Long-Term Support (LTS) release from the official Node.js website. Verify the installation:

```bash
node --version
npm --version
```

Create a project:

```bash
mkdir nodejs-learning
cd nodejs-learning
npm init -y
```

To use ES modules, add `"type": "module"` to `package.json`. Alternatively, use `.mjs` files. This tutorial uses ES modules.

## 3. Your First Program

Create `app.js`:

```javascript
console.log("Hello, Node.js!");
```

Run it:

```bash
node app.js
```

Unlike browser JavaScript, Node.js can access many server-side APIs, such as file-system and network APIs, subject to operating-system permissions and the runtime environment.

## 4. Node.js and npm

Node.js runs JavaScript. npm is a package manager commonly used to install dependencies and run project scripts.

Install a package:

```bash
npm install express
```

Install a development dependency:

```bash
npm install --save-dev nodemon
```

Example scripts in `package.json`:

```json
{
  "type": "module",
  "scripts": {
    "start": "node app.js",
    "dev": "nodemon app.js"
  }
}
```

Keep other fields generated by npm; this snippet only demonstrates the relevant configuration.

Run the development script:

```bash
npm run dev
```

### Important npm files

- `package.json` — project metadata, scripts, and dependency ranges.
- `package-lock.json` — records the resolved dependency tree for reproducible installs.
- `node_modules/` — installed packages; normally do not commit this directory.

Use `npm ci` in CI environments when a lockfile is committed and you want a clean, reproducible install.

## 5. Modules: CommonJS and ES Modules

Modules help split code into reusable files.

### ES modules

`math.js`:

```javascript
export function add(a, b) {
  return a + b;
}
```

`app.js`:

```javascript
import { add } from "./math.js";

console.log(add(5, 3));
```

### Default export

```javascript
export default function greet(name) {
  return `Hello, ${name}`;
}
```

Import it:

```javascript
import greet from "./greet.js";
console.log(greet("Yogi"));
```

### CommonJS

Older or CommonJS-configured projects often use `require()` and `module.exports`:

```javascript
const path = require("node:path");

module.exports = { example: true };
```

Do not mix module systems without understanding how your project is configured. The file extension and `package.json` settings affect how Node.js interprets files.

## 6. Global Objects

Some commonly used globals include:

- `console` — logging
- `process` — information about and control over the current process
- `Buffer` — working with binary data
- `setTimeout()` and `setInterval()` — schedule callbacks
- `URL` — parse and construct URLs

In ES modules, `__dirname` and `__filename` are not available in the same way as in CommonJS. Derive a file path from `import.meta.url` when needed:

```javascript
import { fileURLToPath } from "node:url";
import path from "node:path";

const filename = fileURLToPath(import.meta.url);
const dirname = path.dirname(filename);

console.log({ filename, dirname });
```

## 7. Working with Files

Use the built-in `node:fs/promises` API for promise-based file operations.

```javascript
import { readFile, writeFile } from "node:fs/promises";

await writeFile("notes.txt", "Learning Node.js", "utf8");

const content = await readFile("notes.txt", "utf8");
console.log(content);
```

### Read a JSON file

```javascript
import { readFile } from "node:fs/promises";

const text = await readFile("data.json", "utf8");
const data = JSON.parse(text);

console.log(data);
```

`JSON.parse()` throws if the file does not contain valid JSON. Handle that error when the file content is not fully controlled by your application.

### File-system best practices

- Use asynchronous APIs for most server-side file operations.
- Avoid building paths from untrusted input without validation.
- Handle missing files and permission errors.
- Do not store secrets in public directories.
- For user uploads, validate content and store files safely.

## 8. Asynchronous JavaScript

Server applications often wait for databases, files, or network requests. Asynchronous operations allow Node.js to continue processing other work while waiting.

### Promises

```javascript
const promise = new Promise((resolve) => {
  setTimeout(() => resolve("Finished"), 500);
});

promise.then((value) => console.log(value));
```

### async/await

```javascript
function delay(ms) {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

async function main() {
  await delay(500);
  console.log("Finished");
}

main().catch(console.error);
```

### Handle errors

```javascript
async function loadData() {
  try {
    const result = await fetch("https://example.com/data");
    if (!result.ok) {
      throw new Error(`HTTP error: ${result.status}`);
    }
    return await result.json();
  } catch (error) {
    console.error("Could not load data:", error.message);
    throw error;
  }
}
```

This example uses the global `fetch` available in modern supported Node.js releases. Check the runtime version for the APIs your project needs.

### Run independent tasks concurrently

```javascript
const [users, products] = await Promise.all([
  getUsers(),
  getProducts()
]);
```

This assumes `getUsers()` and `getProducts()` are defined. `Promise.all()` rejects if any input promise rejects. Use `Promise.allSettled()` when you need each task's outcome independently.

## 9. The Event Loop

The event loop lets Node.js coordinate JavaScript execution with asynchronous operations. Many I/O operations can be handled without blocking the main JavaScript thread.

Key concepts:

- **Call stack:** tracks currently executing JavaScript functions.
- **Event loop:** coordinates when queued callbacks and tasks can run.
- **Promises and microtasks:** schedule promise reactions for execution at defined points.
- **I/O callbacks:** run when their associated operations are ready.
- **Blocking work:** long synchronous tasks prevent other JavaScript callbacks from running promptly.

Avoid expensive synchronous work in request handlers. For CPU-heavy tasks, consider worker threads or a separate service.

## 10. Events and EventEmitter

Node.js uses events in many APIs. You can also create your own event emitter.

```javascript
import { EventEmitter } from "node:events";

const emitter = new EventEmitter();

emitter.on("taskCreated", (task) => {
  console.log("New task:", task.title);
});

emitter.emit("taskCreated", { title: "Learn Node.js" });
```

Use events to decouple components when appropriate. Remember that `EventEmitter` listeners run within the same process; this is not a durable job queue or a cross-server messaging system.

## 11. Buffers and Streams

### Buffers

A `Buffer` represents binary data:

```javascript
const buffer = Buffer.from("Hello", "utf8");

console.log(buffer);
console.log(buffer.toString("utf8"));
```

Buffers are useful when working with files, network protocols, and binary content.

### Streams

Streams process data incrementally instead of loading the entire resource into memory.

```javascript
import { createReadStream, createWriteStream } from "node:fs";
import { pipeline } from "node:stream/promises";

await pipeline(
  createReadStream("large-input.txt"),
  createWriteStream("large-output.txt")
);
```

The files must exist or be writable as appropriate. `pipeline()` helps propagate stream errors and clean up the pipeline.

Stream types include readable, writable, duplex, and transform streams.

## 12. Create an HTTP Server

Node.js includes a built-in HTTP module.

Create `server.js`:

```javascript
import { createServer } from "node:http";

const server = createServer((req, res) => {
  if (req.method === "GET" && req.url === "/") {
    res.writeHead(200, { "Content-Type": "application/json" });
    res.end(JSON.stringify({ message: "Hello from Node.js" }));
    return;
  }

  res.writeHead(404, { "Content-Type": "application/json" });
  res.end(JSON.stringify({ message: "Route not found" }));
});

server.listen(5000, () => {
  console.log("Server running at http://localhost:5000");
});
```

This basic server demonstrates request handling. A real server needs careful URL parsing, request-body handling, validation, timeouts, and error management.

## 13. Environment Variables

Environment variables configure an app without hard-coding environment-specific values.

```javascript
const port = Number(process.env.PORT) || 5000;

console.log(`Configured port: ${port}`);
```

A `.env` file can be used during development with a suitable loader, or with built-in environment-file support in Node.js versions that provide it. Keep `.env` out of version control.

Example `.env`:

```text
PORT=5000
MONGODB_URI=mongodb://127.0.0.1:27017
```

Never commit real passwords, API keys, or signing secrets. In production, use your hosting platform's secret-management facility where possible.

## 14. Error Handling

Handle expected errors explicitly and log unexpected errors securely.

```javascript
import { readFile } from "node:fs/promises";

async function readConfig() {
  try {
    return await readFile("config.json", "utf8");
  } catch (error) {
    if (error.code === "ENOENT") {
      throw new Error("Configuration file is missing", { cause: error });
    }
    throw error;
  }
}
```

At the top level, handle failures intentionally:

```javascript
readConfig()
  .then((config) => console.log(config))
  .catch((error) => {
    console.error("Startup failed:", error.message);
    process.exitCode = 1;
  });
```

Avoid empty `catch` blocks. Do not expose secrets, credentials, or full internal stack traces to end users.

## 15. Build a Small REST API

For a structured API, many Node.js developers use Express.js. Install it:

```bash
npm install express
```

Create `app.js`:

```javascript
import express from "express";
import { randomUUID } from "node:crypto";

const app = express();
app.use(express.json());

let tasks = [];

app.get("/api/tasks", (req, res) => {
  res.json(tasks);
});

app.post("/api/tasks", (req, res) => {
  const title = typeof req.body.title === "string"
    ? req.body.title.trim()
    : "";

  if (!title) {
    return res.status(400).json({ message: "A title is required" });
  }

  const task = {
    id: randomUUID(),
    title,
    completed: false
  };

  tasks.push(task);
  res.status(201).json(task);
});

app.get("/api/tasks/:id", (req, res) => {
  const task = tasks.find((item) => item.id === req.params.id);

  if (!task) {
    return res.status(404).json({ message: "Task not found" });
  }

  res.json(task);
});

const PORT = process.env.PORT || 5000;
app.listen(PORT, () => console.log(`API listening on ${PORT}`));
```

This is an in-memory learning example: records disappear when the process restarts, and it does not implement authentication or update/delete routes. Expand it with a database, validation, centralized errors, authorization, and automated tests before using it as a real application.

## 16. Connect Node.js to MongoDB

Install the official MongoDB driver:

```bash
npm install mongodb dotenv
```

Create `.env`:

```text
MONGODB_URI=mongodb://127.0.0.1:27017
MONGODB_DB=nodeLearning
```

Create `database.js`:

```javascript
import "dotenv/config";
import { MongoClient } from "mongodb";

const uri = process.env.MONGODB_URI;

if (!uri) {
  throw new Error("MONGODB_URI is required");
}

const client = new MongoClient(uri);

export async function connectDatabase() {
  await client.connect();
  return client.db(process.env.MONGODB_DB || "nodeLearning");
}

export { client };
```

Use the returned database to access a collection:

```javascript
const db = await connectDatabase();
const tasks = db.collection("tasks");

const result = await tasks.insertOne({
  title: "Practice Node.js",
  completed: false
});

console.log(result.insertedId);
```

In a real server, connect once during startup and reuse the client rather than opening a new connection for every request. Close the client during graceful shutdown.

## 17. Security Best Practices

- Validate all external input, including HTTP bodies, query parameters, and uploaded files.
- Keep dependencies updated and review advisories.
- Never commit secrets or expose them in client-side code.
- Use least-privilege database credentials.
- Use HTTPS in production.
- Apply authentication and authorization to protected routes.
- Avoid unsafe dynamic command execution and unsafe file paths.
- Set request size and timeout limits.
- Rate-limit sensitive endpoints when appropriate.
- Avoid logging passwords, tokens, cookies, or other sensitive data.
- Keep error messages safe for clients while preserving useful server-side diagnostics.
- Use a suitable password-hashing algorithm for passwords; do not store plain-text passwords.

Security is a system-wide concern. A single package or middleware does not make an application secure by itself.

## 18. Testing and Debugging

Node.js has a built-in test runner.

Create `math.js`:

```javascript
export function add(a, b) {
  return a + b;
}
```

Create `math.test.js`:

```javascript
import test from "node:test";
import assert from "node:assert/strict";
import { add } from "./math.js";

test("add returns the sum of two numbers", () => {
  assert.equal(add(2, 3), 5);
});
```

Run the test:

```bash
node --test
```

For more complex applications, test modules, API routes, database behavior, authentication, and failure cases. Use isolated test data and never run destructive tests against production systems.

### Debugging tips

- Read the complete error message and stack trace.
- Reproduce the issue with a small example.
- Use the Node.js inspector or your editor's debugger.
- Add meaningful logs without logging secrets.
- Check environment variables and runtime versions.
- Test both success and failure paths.

## 19. Deploying a Node.js App

A typical deployment process:

1. Commit application code and the lockfile.
2. Configure environment variables in the hosting platform.
3. Install dependencies with a reproducible command.
4. Run tests and any required build steps.
5. Start the app with the configured start script.
6. Confirm health checks and logs.
7. Configure HTTPS, domains, and a reverse proxy if needed.
8. Set up monitoring and a rollback strategy.

The hosting platform determines the exact deployment steps. Do not assume every provider requires a VPS or the same process manager.

## 20. Node.js with Express.js and Next.js

### Node.js and Express.js

Node.js is the runtime; Express.js is a framework built on Node.js. Express adds routing, middleware, and HTTP helpers.

### Node.js and Next.js

Next.js runs on Node.js in common deployment modes and provides frontend plus server-side capabilities such as Route Handlers and Server Components. You do not always need a separate Express server for a Next.js application.

A separate Express API can make sense when several clients share the same backend, when you need an independent service, or when an existing system already uses Express.

## 21. Recommended Project Structure

For a growing Express API:

```text
node-api/
├── src/
│   ├── config/
│   │   └── database.js
│   ├── controllers/
│   ├── middleware/
│   ├── models/
│   ├── routes/
│   ├── services/
│   ├── app.js
│   └── server.js
├── tests/
├── .env
├── .gitignore
└── package.json
```

- **Routes:** define endpoints and middleware.
- **Controllers:** handle HTTP input and output.
- **Services:** implement reusable business logic.
- **Models:** define database interaction and schemas.
- **Middleware:** provide authentication, validation, logging, and error handling.
- **Config:** manage database and application setup.
- **Tests:** verify expected behavior.

Use a structure that matches the size of your application; a small script does not need every folder.

## 23. Interview Questions and Answers

### 1. What is Node.js?

Node.js is a JavaScript runtime that allows JavaScript to run outside the browser.

### 2. Is Node.js a programming language?

No. JavaScript is the language; Node.js is a runtime environment.

### 3. What is npm?

npm is a package manager commonly used to install JavaScript packages and run project scripts.

### 4. What is the V8 engine?

V8 is the JavaScript engine used by Node.js to compile and execute JavaScript.

### 5. What is the difference between Node.js and Express.js?

Node.js is the runtime. Express.js is a web framework that runs on Node.js.

### 6. What is an event loop?

The event loop coordinates the execution of JavaScript callbacks and asynchronous work so Node.js can handle many I/O operations efficiently.

### 7. What is asynchronous programming?

It allows a program to start an operation and continue other work while waiting for the operation to complete.

### 8. What is a Promise?

A Promise represents the eventual success or failure of an asynchronous operation.

### 9. What does `async/await` do?

It provides syntax for working with Promises in a style that resembles sequential code. Errors can be handled with `try/catch`.

### 10. What is a callback?

A callback is a function passed to another function to be called later or when an operation reaches a particular point.

### 11. What is callback hell?

It is deeply nested callback code that becomes difficult to read and maintain. Promises and `async/await` can improve structure.

### 12. What are modules?

Modules split code into separate files with explicit exports and imports or other module-system conventions.

### 13. What is the difference between CommonJS and ES modules?

CommonJS commonly uses `require()` and `module.exports`. ES modules use `import` and `export`.

### 14. What is `package.json`?

It describes project metadata, scripts, dependencies, and other package configuration.

### 15. What is `package-lock.json`?

It records the resolved dependency tree to support more reproducible dependency installation.

### 16. What is the `process` object?

It provides information and controls for the current Node.js process, including environment variables and process events.

### 17. What are environment variables?

They provide configuration to an application from its execution environment rather than hard-coding values in source code.

### 18. What is a Buffer?

A Buffer represents binary data, such as bytes read from a file or received from a network.

### 19. What are streams?

Streams process data incrementally, which can reduce memory usage for large data sources.

### 20. Name the main types of streams.

Readable, writable, duplex, and transform.

### 21. What is EventEmitter?

It is a Node.js API for registering listeners and emitting named events.

### 22. What is blocking code?

Blocking code prevents the main JavaScript thread from continuing other JavaScript work until the operation completes.

### 23. How can you handle CPU-intensive work?

Consider worker threads, separate worker processes, or a dedicated service, depending on the workload.

### 24. How do you create an HTTP server?

Use Node.js's built-in `node:http` module or a framework such as Express.js.

### 25. How does Node.js connect to MongoDB?

Use the official MongoDB driver or an ODM such as Mongoose, and reuse the connection appropriately.

### 26. Why use `try/catch` with `async/await`?

It allows code to handle rejected Promises and other thrown errors in a controlled way.

### 27. What is `Promise.all()`?

It waits for all input Promises to fulfill, or rejects as soon as one rejects. It is useful for independent asynchronous tasks.

### 28. What is the difference between `Promise.all()` and `Promise.allSettled()`?

`Promise.all()` rejects if any input rejects. `Promise.allSettled()` waits for all inputs and returns each outcome.

### 29. How should passwords be stored?

Store password hashes produced by a suitable password-hashing algorithm, not plain-text passwords.

### 30. How do you improve a Node.js application's reliability?

Use validation, error handling, automated tests, health checks, structured logs, monitoring, safe configuration, and graceful shutdown.

### 31. Why should secrets not be committed to Git?

Repository history can persist and be copied. Use environment configuration or a secrets manager, and rotate any secret that has been exposed.

### 32. What is graceful shutdown?

It stops new work when appropriate, allows ongoing requests to finish where possible, closes resources, and exits cleanly.

### 33. What is the difference between `readFile()` and `createReadStream()`?

`readFile()` reads a file into memory before resolving. A read stream delivers data in chunks, which is often better for large files.

### 34. How do you test Node.js code?

Use the built-in test runner or a testing framework and cover expected behavior, edge cases, and failure conditions.

### 35. Is Node.js suitable for every application?

No. It is strong for many I/O-heavy services, but CPU-intensive workloads may need workers or other architectures. Choose based on the application's requirements.

## Conclusion

Node.js provides the runtime and built-in APIs needed to build server-side JavaScript applications. Learn modules, asynchronous programming, the event loop, files, streams, and HTTP first. Then build REST APIs, connect a database, add security, write tests, and deploy a complete project.

For a practical learning path, combine this guide with an Express.js tutorial, MongoDB, authentication, and a frontend project. Build, test, document, and deploy each project so your understanding goes beyond syntax.
