# Express.js Tutorial

Express.js is a minimal web framework for Node.js. It provides tools for routing, middleware, request handling, and building HTTP APIs. This guide introduces Express from the basics and gradually covers REST API design, validation, authentication, security, testing, and production practices.

Examples use modern JavaScript with ES modules. They are educational starting points; production applications also need careful configuration, monitoring, authorization, and error handling.

## 1. What Is Express.js?

Express.js is a web framework that runs on Node.js. It helps developers build web servers and APIs without manually handling every low-level HTTP detail.

### Common uses

- REST APIs
- Backend services for React applications
- Authentication and authorization endpoints
- Database-backed applications
- Webhooks and integrations
- Server-rendered websites and small web services

Node.js provides the JavaScript runtime and networking APIs. Express adds routing and middleware abstractions on top.

## 2. Prerequisites

Before learning Express, become familiar with:

- JavaScript fundamentals, including functions, arrays, and objects
- ES modules (`import` and `export`)
- Promises and `async`/`await`
- HTTP methods, headers, status codes, and JSON
- Basic Node.js and npm commands
- Basic database concepts

You can learn Express while strengthening these skills, but understanding asynchronous JavaScript is particularly important.

## 3. Create an Express Project

Install a current supported Node.js release. Create a project:

```bash
mkdir express-api
cd express-api
npm init -y
npm install express
npm install --save-dev nodemon
```

To use ES modules, add `"type": "module"` to `package.json`, and add scripts such as:

```json
{
  "type": "module",
  "scripts": {
    "start": "node server.js",
    "dev": "nodemon server.js"
  }
}
```

Keep the rest of the `package.json` fields generated by npm. The example above only shows the relevant fields.

## 4. Your First Express Server

Create `server.js`:

```javascript
import express from "express";

const app = express();
const PORT = process.env.PORT || 5000;

app.get("/", (req, res) => {
  res.send("Hello from Express.js!");
});

app.listen(PORT, () => {
  console.log(`Server listening on port ${PORT}`);
});
```

Run it:

```bash
npm run dev
```

Open `http://localhost:5000/` in a browser. You should see the response text.

The server listens for HTTP requests and uses the matching route to produce a response. In production, your hosting platform may supply the port through the `PORT` environment variable.

## 5. HTTP Methods and Status Codes

HTTP methods communicate the intended operation.

| Method | Common use |
|---|---|
| `GET` | Read a resource |
| `POST` | Create a resource or perform an operation |
| `PUT` | Replace a resource |
| `PATCH` | Partially update a resource |
| `DELETE` | Delete a resource |

Common status codes:

| Code | Meaning |
|---|---|
| `200 OK` | Request succeeded |
| `201 Created` | A resource was created |
| `204 No Content` | Request succeeded with no response body |
| `400 Bad Request` | Request data is invalid |
| `401 Unauthorized` | Authentication is missing or invalid |
| `403 Forbidden` | The caller is not allowed to perform the action |
| `404 Not Found` | Resource or route was not found |
| `409 Conflict` | Request conflicts with current resource state |
| `429 Too Many Requests` | Rate limit was exceeded |
| `500 Internal Server Error` | Unexpected server failure |

Use status codes consistently. Do not return `200` for every outcome.

## 6. Routing

A route combines an HTTP method and a path with a handler.

```javascript
app.get("/about", (req, res) => {
  res.json({ page: "About" });
});

app.post("/messages", (req, res) => {
  res.status(201).json({ message: "Message endpoint called" });
});
```

### Route parameters

```javascript
app.get("/users/:userId", (req, res) => {
  res.json({ userId: req.params.userId });
});
```

For `/users/123`, the parameter is available as `req.params.userId`.

### Query parameters

For a request such as `/products?category=books&page=2`:

```javascript
app.get("/products", (req, res) => {
  const { category, page } = req.query;
  res.json({ category, page });
});
```

Query values are user-controlled input. Validate their types, allowed values, and ranges before using them.

### Express Router

Split related routes into a separate module.

`routes/users.js`:

```javascript
import { Router } from "express";

const router = Router();

router.get("/", (req, res) => {
  res.json([{ id: "1", name: "Yogi" }]);
});

router.get("/:id", (req, res) => {
  res.json({ id: req.params.id });
});

export default router;
```

In `server.js`:

```javascript
import usersRouter from "./routes/users.js";

app.use("/api/users", usersRouter);
```

The router's `/` route becomes `/api/users`, and `/:id` becomes `/api/users/:id`.

## 7. Request and Response Objects

Express provides `req` (request) and `res` (response).

Common request properties:

- `req.params` — route parameters
- `req.query` — query-string parameters
- `req.body` — parsed request body when suitable middleware is configured
- `req.headers` — request headers
- `req.method` — HTTP method
- `req.path` — request path

Common response methods:

```javascript
res.send("Text response");
res.json({ success: true });
res.status(201).json({ id: "123" });
res.sendStatus(204);
```

A request body is not automatically parsed by every Express application. Add appropriate body-parsing middleware before routes.

## 8. Middleware

Middleware functions can inspect or change the request and response, end the request, or pass control to the next middleware.

A middleware function commonly has the signature `(req, res, next)`:

```javascript
function requestLogger(req, res, next) {
  console.log(`${req.method} ${req.originalUrl}`);
  next();
}
```

Register it before the routes it should affect:

```javascript
app.use(requestLogger);
```

### Built-in middleware

```javascript
app.use(express.json());
app.use(express.urlencoded({ extended: false }));
```

- `express.json()` parses JSON request bodies.
- `express.urlencoded()` parses URL-encoded form bodies.

### Middleware order matters

```javascript
app.use(express.json());
app.use(requestLogger);

app.get("/health", (req, res) => {
  res.json({ status: "ok" });
});
```

Middleware executes in registration order. If middleware sends a response without calling `next()`, later handlers do not run for that request.

### Error-handling middleware

Error handlers have four parameters:

```javascript
function errorHandler(err, req, res, next) {
  console.error(err);

  if (res.headersSent) {
    return next(err);
  }

  res.status(err.status || 500).json({
    message: err.status && err.status < 500
      ? err.message
      : "Internal server error"
  });
}
```

Register the error handler after routes. Avoid sending stack traces, secrets, or database internals to clients in production.

## 9. Building a REST API

A REST-style API models resources with URLs and HTTP methods. The following example keeps data in memory to teach the request flow. The data resets when the server restarts, so use a database for real applications.

```javascript
import express from "express";
import { randomUUID } from "node:crypto";

const app = express();
app.use(express.json());

let tasks = [
  { id: "task-1", title: "Learn Express", completed: false }
];

app.get("/api/tasks", (req, res) => {
  res.json(tasks);
});

app.get("/api/tasks/:id", (req, res) => {
  const task = tasks.find((item) => item.id === req.params.id);

  if (!task) {
    return res.status(404).json({ message: "Task not found" });
  }

  res.json(task);
});

app.post("/api/tasks", (req, res) => {
  const title = typeof req.body.title === "string"
    ? req.body.title.trim()
    : "";

  if (!title) {
    return res.status(400).json({ message: "Title is required" });
  }

  const task = {
    id: randomUUID(),
    title,
    completed: false
  };

  tasks.push(task);
  res.status(201).json(task);
});

app.patch("/api/tasks/:id", (req, res) => {
  const task = tasks.find((item) => item.id === req.params.id);

  if (!task) {
    return res.status(404).json({ message: "Task not found" });
  }

  if (typeof req.body.title === "string") {
    const title = req.body.title.trim();

    if (!title) {
      return res.status(400).json({ message: "Title cannot be empty" });
    }

    task.title = title;
  }

  if (typeof req.body.completed === "boolean") {
    task.completed = req.body.completed;
  }

  res.json(task);
});

app.delete("/api/tasks/:id", (req, res) => {
  const index = tasks.findIndex((item) => item.id === req.params.id);

  if (index === -1) {
    return res.status(404).json({ message: "Task not found" });
  }

  tasks.splice(index, 1);
  res.status(204).end();
});

app.listen(5000, () => console.log("API listening on port 5000"));
```

Test the API with Postman, Insomnia, or `curl`.

Create a task:

```bash
curl -X POST http://localhost:5000/api/tasks \
  -H "Content-Type: application/json" \
  -d '{"title":"Build a REST API"}'
```

List tasks:

```bash
curl http://localhost:5000/api/tasks
```

For a real API, also implement persistent storage, validation, authorization, rate limiting where appropriate, and tests.

## 10. Validation and Error Handling

Never assume incoming data is valid. Validate request bodies, query parameters, route parameters, and file uploads.

A small manual validator can help demonstrate the idea:

```javascript
function validateTask(req, res, next) {
  const { title, completed } = req.body ?? {};

  if (typeof title !== "string" || title.trim().length < 1) {
    return res.status(400).json({
      message: "Title must be a non-empty string"
    });
  }

  if (completed !== undefined && typeof completed !== "boolean") {
    return res.status(400).json({
      message: "Completed must be a boolean"
    });
  }

  next();
}
```

Use it on the relevant route:

```javascript
app.post("/api/tasks", validateTask, createTask);
```

Here, `createTask` must be a route handler defined elsewhere. For larger applications, validation libraries can express schemas more clearly.

### Centralized errors

Instead of duplicating error responses, pass unexpected errors to a centralized error handler. In current Express versions, rejected promises from async route handlers are forwarded automatically; with older versions, use a wrapper or explicitly pass errors to `next(err)`.

Example:

```javascript
app.get("/api/example", async (req, res, next) => {
  try {
    const result = await performAsyncOperation();
    res.json(result);
  } catch (error) {
    next(error);
  }
});
```

This example assumes `performAsyncOperation()` is implemented elsewhere.

## 11. Connecting MongoDB

MongoDB stores application data persistently. You can use the official driver or Mongoose. The driver is direct; Mongoose adds schema and model features.

Install the driver:

```bash
npm install mongodb dotenv
```

Create `.env`:

```text
MONGODB_URI=mongodb://127.0.0.1:27017
MONGODB_DB=expressDemo
PORT=5000
```

Add `.env` to `.gitignore`. Never commit real credentials.

Create a shared connection module, `db.js`:

```javascript
import "dotenv/config";
import { MongoClient } from "mongodb";

const uri = process.env.MONGODB_URI;

if (!uri) {
  throw new Error("MONGODB_URI is missing");
}

const client = new MongoClient(uri);
let database;

export async function connectDB() {
  if (!database) {
    await client.connect();
    database = client.db(process.env.MONGODB_DB || "expressDemo");
  }

  return database;
}

export { client };
```

Then connect before accepting requests:

```javascript
import express from "express";
import { connectDB } from "./db.js";

const app = express();
app.use(express.json());

app.get("/api/health", (req, res) => {
  res.json({ status: "ok" });
});

const PORT = process.env.PORT || 5000;

connectDB()
  .then(() => {
    app.listen(PORT, () => {
      console.log(`Server running on port ${PORT}`);
    });
  })
  .catch((error) => {
    console.error("Database connection failed:", error);
    process.exitCode = 1;
  });
```

This startup pattern shows the idea. A production application should define graceful shutdown behavior and close the database client on termination.

## 12. Using Mongoose Models

Install Mongoose:

```bash
npm install mongoose
```

Define a model:

```javascript
import mongoose from "mongoose";

const taskSchema = new mongoose.Schema(
  {
    title: {
      type: String,
      required: true,
      trim: true,
      minlength: 1,
      maxlength: 200
    },
    completed: {
      type: Boolean,
      default: false
    },
    owner: {
      type: mongoose.Schema.Types.ObjectId,
      ref: "User",
      required: true
    }
  },
  { timestamps: true }
);

export const Task = mongoose.model("Task", taskSchema);
```

Connect using the configured URI:

```javascript
import mongoose from "mongoose";

await mongoose.connect(process.env.MONGODB_URI);
```

Use models in routes or, preferably as an application grows, in service/controller layers:

```javascript
const tasks = await Task.find({ owner: userId })
  .sort({ createdAt: -1 })
  .lean();
```

`userId` must come from a trusted authentication context, not simply from an untrusted query parameter. A production API should scope reads and updates to the authenticated user's permitted records.

## 13. Authentication and Authorization

Authentication answers “Who are you?” Authorization answers “What are you allowed to do?”

A typical API flow:

1. A user registers with an email and password.
2. The server validates the input and checks account rules.
3. The server hashes the password with a suitable password-hashing algorithm.
4. The user signs in with credentials.
5. The server creates a session or issues a token.
6. Protected routes verify the session or token.
7. Authorization checks whether the authenticated user may access the requested resource.

### Password hashing

Do not store plain-text passwords. Use a password-hashing library such as Argon2id or bcrypt with appropriate parameters. Passwords should not be encrypted reversibly for ordinary login storage.

Illustrative example with bcrypt:

```bash
npm install bcrypt
```

```javascript
import bcrypt from "bcrypt";

const passwordHash = await bcrypt.hash(password, 12);
const passwordMatches = await bcrypt.compare(
  submittedPassword,
  passwordHash
);
```

The example assumes `password` and `submittedPassword` have already been validated. Choose hashing parameters based on current security guidance and the server's capacity.

### Token-based authentication

A token-based flow may use a signed access token. Keep signing keys in environment variables or a secrets manager, validate token signature and claims, and use short lifetimes where appropriate.

Illustrative middleware using `jsonwebtoken`:

```bash
npm install jsonwebtoken
```

```javascript
import jwt from "jsonwebtoken";

function requireAuth(req, res, next) {
  const header = req.headers.authorization;
  const [scheme, token] = header?.split(" ") ?? [];

  if (scheme !== "Bearer" || !token) {
    return res.status(401).json({ message: "Authentication required" });
  }

  try {
    req.user = jwt.verify(token, process.env.JWT_SECRET);
    next();
  } catch {
    return res.status(401).json({ message: "Invalid or expired token" });
  }
}
```

This is an educational pattern, not a complete authentication system. Configure allowed algorithms and expected issuer/audience as appropriate, validate required claims, manage secret rotation, and avoid placing sensitive data in token payloads. Never hard-code `JWT_SECRET` or use a sample value in production.

Use middleware on protected routes:

```javascript
app.get("/api/private", requireAuth, (req, res) => {
  res.json({ message: "You are authenticated" });
});
```

### Authorization example

A user should only update their own task unless a role or policy grants broader access. Apply ownership in the database filter:

```javascript
const updatedTask = await Task.findOneAndUpdate(
  { _id: req.params.id, owner: req.user.id },
  { $set: { completed: true } },
  { new: true, runValidators: true }
);
```

If no task matches, respond appropriately without leaking whether another user's private record exists. Ensure `req.user.id` is populated by a trusted authentication middleware and validate the ID format.

### Cookies and sessions

For browser applications, server-side sessions stored in secure cookies can be a good choice. Use `HttpOnly`, `Secure` in HTTPS production, and an appropriate `SameSite` setting. Consider CSRF protection when using cookies for authentication. The best choice depends on your app architecture and threat model.

## 14. Security Best Practices

### Use security middleware

Install commonly used packages:

```bash
npm install helmet express-rate-limit
```

Example:

```javascript
import helmet from "helmet";
import rateLimit from "express-rate-limit";

app.use(helmet());

app.use("/api", rateLimit({
  windowMs: 15 * 60 * 1000,
  limit: 100,
  standardHeaders: "draft-8",
  legacyHeaders: false
}));
```

Check package documentation for the version you install and tune rate limits for your users, deployment, and endpoints. Login and password-reset routes may need stricter limits.

### Security checklist

- Use HTTPS in production.
- Validate all untrusted inputs.
- Use parameterized or structured database operations.
- Apply authorization on every protected resource.
- Avoid mass assignment by allowlisting writable fields.
- Configure CORS to allow only trusted origins where possible.
- Protect cookies and implement CSRF controls when needed.
- Use rate limiting for abuse-prone endpoints.
- Do not expose stack traces or internal errors to clients.
- Keep dependencies updated.
- Set request-size limits.
- Keep secrets out of source control and client-side bundles.

## 15. Environment Variables and Configuration

Environment variables keep configuration separate from source code.

Example `.env`:

```text
PORT=5000
MONGODB_URI=mongodb://127.0.0.1:27017
MONGODB_DB=expressDemo
JWT_SECRET=replace-with-a-long-random-secret
```

The value shown for `JWT_SECRET` is a placeholder; generate a strong secret for development and production, and do not commit it. Production deployments should use their platform's secret-management mechanism where available.

Load variables early:

```javascript
import "dotenv/config";

const PORT = process.env.PORT || 5000;
```

Validate required configuration at startup and fail fast if essential variables are missing.

## 16. CORS and Cookies

Cross-Origin Resource Sharing (CORS) is a browser mechanism that controls whether frontend code from one origin can read a response from another origin.

Install the CORS package:

```bash
npm install cors
```

Configure a known frontend origin:

```javascript
import cors from "cors";

app.use(cors({
  origin: process.env.CLIENT_ORIGIN,
  credentials: true
}));
```

If you use credentials such as cookies, the server must use an explicit allowed origin rather than `*`, and the browser request must opt into credentials. CORS is not authentication and does not prevent non-browser clients from calling your API.

### Cookie example

```javascript
res.cookie("session", sessionValue, {
  httpOnly: true,
  secure: process.env.NODE_ENV === "production",
  sameSite: "lax",
  maxAge: 60 * 60 * 1000
});
```

This is illustrative. A real system must securely generate and verify the session value, decide whether cookie-based authentication is appropriate, configure domain/path correctly, and provide logout/session invalidation. `HttpOnly` prevents normal JavaScript access to the cookie but does not itself prevent CSRF.

## 17. File Uploads

Multipart file uploads often use middleware such as Multer.

```bash
npm install multer
```

Basic example:

```javascript
import multer from "multer";

const upload = multer({
  dest: "uploads/",
  limits: {
    fileSize: 5 * 1024 * 1024,
    files: 1
  }
});

app.post("/api/upload", upload.single("file"), (req, res) => {
  if (!req.file) {
    return res.status(400).json({ message: "File is required" });
  }

  res.status(201).json({
    message: "Upload received",
    originalName: req.file.originalname,
    size: req.file.size
  });
});
```

This example stores files temporarily on the server's filesystem and is not a complete production upload service. Production upload handling should validate file type and content, generate safe server-side filenames, scan or process risky files when appropriate, control access, and consider object storage. Do not trust the client-supplied filename or MIME type alone.

## 18. Testing an Express API

Automated tests help confirm that routes behave correctly.

Common tools include:

- Node.js built-in test runner
- Vitest or Jest
- Supertest for HTTP testing
- A dedicated test database

Install Supertest and a test runner if needed:

```bash
npm install --save-dev supertest
```

Example test pattern:

```javascript
import request from "supertest";
import { test } from "node:test";
import assert from "node:assert/strict";
import app from "./app.js";

test("GET /api/health returns status ok", async () => {
  const response = await request(app).get("/api/health");

  assert.equal(response.status, 200);
  assert.deepEqual(response.body, { status: "ok" });
});
```

This assumes `app.js` exports the Express app without calling `listen()` at import time. Keep server startup in a separate entry file to make testing easier.

Test cases should cover successful requests, invalid input, missing resources, unauthenticated access, forbidden access, and unexpected failures. Use isolated test data and do not run destructive tests against production databases.

## 19. Logging and Production Readiness

Production services need visibility into what they are doing.

- Log request method, route, status, and duration.
- Use structured logs for easier filtering.
- Avoid logging passwords, access tokens, cookies, or sensitive personal data.
- Add a health endpoint for basic availability checks.
- Handle process termination gracefully.
- Close database connections on shutdown.
- Use monitoring and alerting for latency and error rates.
- Configure reverse proxies and trusted proxy settings carefully.
- Set appropriate request body and upload size limits.
- Use a process manager or managed hosting platform to keep services running.

Example health endpoint:

```javascript
app.get("/api/health", (req, res) => {
  res.status(200).json({ status: "ok" });
});
```

A basic health endpoint does not prove the database or every dependency is healthy. Add deeper checks only when useful for your deployment and avoid exposing sensitive operational details publicly.

## 20. Express with React and Next.js

### React frontend

A React app can call an Express API using `fetch()`:

```javascript
async function loadTasks() {
  const response = await fetch("http://localhost:5000/api/tasks");

  if (!response.ok) {
    throw new Error(`Request failed: ${response.status}`);
  }

  return response.json();
}
```

Configure CORS for the development frontend origin if they run on different origins. In production, use appropriate API URLs and secure authentication.

### Next.js

Next.js can use Route Handlers and server-side features for many backend tasks, so a separate Express server is not always necessary. Express may still be useful when you need an independent API service, shared backend for multiple clients, or existing Express middleware and integrations.

Choose one architecture based on actual requirements rather than adding a separate backend automatically.

## 21. Recommended Project Structure

For a small project:

```text
express-api/
├── src/
│   ├── config/
│   │   └── database.js
│   ├── controllers/
│   │   └── taskController.js
│   ├── middleware/
│   │   ├── auth.js
│   │   └── errorHandler.js
│   ├── models/
│   │   └── Task.js
│   ├── routes/
│   │   └── taskRoutes.js
│   ├── services/
│   ├── app.js
│   └── server.js
├── tests/
├── .env
├── .gitignore
└── package.json
```

Suggested responsibilities:

- **Routes:** define paths, HTTP methods, and middleware chains.
- **Controllers:** translate HTTP input into application actions and responses.
- **Services:** hold reusable business logic.
- **Models:** define database access or schemas.
- **Middleware:** authentication, logging, validation, and error handling.
- **Config:** database and environment setup.
- **Tests:** verify behavior without depending on production data.

This is a guideline, not a requirement. Keep the structure as simple as the project allows.

Build a smaller project completely, including validation, tests, README, environment configuration, and deployment, rather than only creating endpoints.

## 23. Interview Questions and Answers

### 1. What is Express.js?

Express.js is a web framework for Node.js that provides routing, middleware, and HTTP request/response helpers.

### 2. What is middleware?

Middleware is a function that can inspect or modify a request/response, end the request, or pass control to the next handler.

### 3. Why does middleware order matter?

Express executes middleware in registration order. A middleware must run before the routes or handlers that depend on it.

### 4. What is routing?

Routing maps an HTTP method and URL path to a handler function.

### 5. What is `req.params`?

It contains route parameters, such as the `id` in `/users/:id`.

### 6. What is `req.query`?

It contains parsed query-string parameters, such as `page=2` in `/posts?page=2`.

### 7. What is `req.body`?

It contains a parsed request body when appropriate body-parsing middleware is configured.

### 8. What is the difference between `res.send()` and `res.json()`?

`res.send()` sends a response using Express's response handling. `res.json()` serializes a value as JSON and sets the JSON content type.

### 9. What is REST?

REST is an architectural style for networked systems. REST-style APIs commonly model resources with URLs and use HTTP methods and status codes consistently.

### 10. What is the difference between PUT and PATCH?

PUT is commonly used to replace a resource representation. PATCH applies a partial modification.

### 11. What is error-handling middleware?

It is middleware with four parameters `(err, req, res, next)` used to handle errors passed through Express's error flow.

### 12. How do you handle errors in async routes?

In current Express versions, rejected promises from async handlers are forwarded to error handling. In older versions, wrap handlers or explicitly pass errors to `next(err)`.

### 13. What is CORS?

CORS is a browser-enforced mechanism that controls whether frontend code from one origin can read responses from another origin.

### 14. What is the difference between authentication and authorization?

Authentication verifies identity. Authorization determines which actions or resources that identity may access.

### 15. How should passwords be stored?

Store password hashes created with a suitable password-hashing algorithm such as Argon2id or bcrypt, not plain-text passwords.

### 16. What is JWT?

JSON Web Token is a compact format for representing claims. A signed JWT can be verified for integrity, but its payload is not automatically encrypted.

### 17. Is JWT the same as a session?

No. JWT is a token format. A session is a server-managed representation of authenticated state; systems can use opaque session IDs or tokens in different architectures.

### 18. What is Helmet?

Helmet is middleware that helps set various HTTP security headers. It does not replace input validation, authorization, or other security controls.

### 19. Why use environment variables?

They separate environment-specific configuration and secrets from application source code. Secrets still need appropriate access controls and safe deployment configuration.

### 20. What is rate limiting?

Rate limiting restricts request frequency or volume to help reduce abuse and protect resources.

### 21. What is Mongoose?

Mongoose is an ODM for Node.js and MongoDB that provides schemas, models, validation, and middleware.

### 22. What is the difference between a controller and a service?

A controller typically handles HTTP-specific input and output. A service contains reusable business logic. The separation is an architectural convention rather than an Express requirement.

### 23. Why validate API input?

Validation rejects malformed or unexpected input early and helps protect business rules and downstream systems. Authorization and database constraints are still necessary.

### 24. What is a REST API status code for successful creation?

`201 Created` is commonly used when a request creates a resource.

### 25. How do you protect a private route?

Authenticate the caller, then authorize the requested action and resource. Do not rely only on hiding buttons in the frontend.

### 26. Why should you not expose stack traces in production?

They can reveal internal paths, implementation details, and sensitive information. Log diagnostic details securely on the server and return a safe error message to clients.

### 27. What is the purpose of `express.json()`?

It parses supported JSON request bodies and makes the parsed value available through `req.body`.

### 28. Why separate app setup from server startup?

Exporting the configured Express app separately makes it easier to test routes without opening a network port.

### 29. Does Express automatically connect to MongoDB?

No. You must configure and create a connection using the MongoDB driver, Mongoose, or another compatible library.

### 30. Is Express required when using Next.js?

No. Next.js provides its own backend capabilities. Express is useful when an independent Node.js API service or Express-specific middleware is needed.

### 31. How can you improve Express API performance?

Measure first. Useful steps can include indexing database queries, avoiding unnecessary work, caching suitable responses, reusing database connections, compressing appropriate responses, and moving long-running tasks to background workers.

### 32. How do you test Express routes?

Use automated tests with tools such as Node's test runner, Vitest, Jest, and Supertest. Test success paths, validation failures, authentication, authorization, and error handling.

### 33. What is a reverse proxy?

A reverse proxy sits in front of an application server and forwards requests. It can handle TLS termination, routing, buffering, or other infrastructure tasks depending on configuration.

### 34. What is graceful shutdown?

Graceful shutdown stops accepting new work, allows in-flight work to finish when possible, closes resources such as database connections, and then exits.

### 35. How should you learn Express.js?

Build a basic server, learn routing and middleware, create CRUD endpoints, connect MongoDB, add validation and authentication, then test and deploy a complete API.

## Conclusion

Express.js makes it straightforward to build HTTP servers and APIs with Node.js. Start with routes, request/response handling, and middleware. Then learn CRUD design, validation, database integration, authentication, authorization, and security.

The most valuable practice is to build a complete API with persistent data, clear error handling, automated tests, and safe configuration. Once comfortable, connect the API to a React or Next.js frontend and deploy it with production monitoring.
